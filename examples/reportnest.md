# Worked brief: a developer's first email program

ReportNest is fictional. It accepts CSV uploads, saves reports, and shares reports using private links. The intended buyer is a freelance bookkeeper. There are 40 signups and nine users with a first report; marketing eligibility is unknown. There is no email provider, testimonial, or paid-services budget.

A useful initial hypothesis is that some new users need help reaching a first report. Nine of forty is a descriptive count, not proof that email will fix the remaining cases. Check the setup path and ask for permission evidence before live enrollment.

The strategy should include capture, welcome, activation, ongoing education, retention, and re-engagement where relevant. Trial or upgrade flows require real pricing/product facts. A first activation flow can help a new user create a sample report, then skip obsolete reminders after the report exists. Use product examples instead of invented social proof.

The local preview uses synthetic recipients and explicitly assigned fixture eligibility. Unknown real eligibility must not become permission to send. Test activation, opt-out while queued, duplicate events, replay, and missing names. The calendar can reserve time for learning instead of filling every week with a promotion.

The executable demonstration lives in [the main skill](../skills/email-marketing/SKILL.md). Runtime evaluation results and limitations are recorded in [validation](../docs/validation.md).
