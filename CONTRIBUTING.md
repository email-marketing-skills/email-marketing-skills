# Contributing

Bring a concrete task the skill mishandles, a minimal synthetic example, the observed output, and what should happen instead. Never include customer lists, secrets, or private message threads.

Keep each skill independently installable. References must travel inside the skill folder. Prefer specific decisions, artifact contracts, examples, and acceptance checks over generic advice. Do not add a tool or provider dependency unless the task requires it; document a useful offline fallback.

Run the structural validator and preview tests. For behavior changes, run the relevant evaluation case with the revised skill and a baseline. Report facts and limitations; do not invent scores or performance claims. An independent reviewer checks the final changes before merge.

Do not submit synthetic installs, stars, automated endorsements, or copied third-party skill packages as contributions. Real usage reports and useful examples are welcome.
