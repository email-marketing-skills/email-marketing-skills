# Write an email with one useful job

Read the product's current claims, audience, offer, flow brief, and voice samples. Ask for a missing goal only when it changes the draft. If no source proves a feature or result, mark it unknown and remove the claim. No network is required for supplied facts; browse primary sources when checking current product claims.

## Draft from the reader's situation

Write the job in one sentence: “Help a new user publish the booking page they started.” Name the relevant reader state, obstacle, available proof, and next action. Choose one angle. A technical reader may need a precise example; a new user may need the next setup step.

Produce three honest subject options with rationale, one preview line, full body, one primary CTA and destination, plain-text version, and merge-field fallbacks. A request for a sequence needs complete copy for every message plus its purpose and timing assumptions. Label fictional examples. Do not present placeholders as send-ready.

## Evidence and voice

Use short paragraphs and specific verbs. Open with the reason for writing. Explain the benefit before listing features. Link to the exact useful page. Subject and preview should complement each other.

Never fabricate a testimonial, ROI, recipient pain, prior conversation, scarcity, or expiring offer. Avoid fake Re:/Fwd:, generic praise, “I hope this finds you well,” feature dumps, and repeated “just checking in.” Do not turn an unsupported claim into a more polished unsupported claim. Replace unavailable proof with a demonstrable product example.

For outbound, connect a cited observation to a plausible use case and ask one easy reply question. Keep internal source notes outside the sent body. A public address is not permission to subscribe.

## Review before handoff

Read [the editing checklist](references/editing.md). Check unresolved tokens, name fallbacks, destination accuracy, contradictions with the current product, CTA count, required sender/footer content, and the mobile/plain-text version. Preserve unsubscribe mechanics. Sending requires the user's scoped authorization; producing copy does not grant it.

Save `marketing/emails.md` with subject options, selected version, rationale, source notes, and any launch blockers. Report what must be confirmed before use. For small audiences, offer a clear hypothesis to test instead of promising a statistically meaningful A/B result.
