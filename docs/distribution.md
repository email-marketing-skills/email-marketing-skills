# Discovery and adoption plan

## Listing mechanics

Skills.sh's [FAQ](https://skills.sh/docs/faq) says installations through `npx skills add owner/repo` feed automatic listing and rankings. The root `skills.sh.json` organizes the repository page after processing. This is not a manual submission or a guarantee of inclusion timing.

Perform one genuine installation for end-to-end validation, then inspect the repository listing. Repeated self-installs, automated installs, fake stars, and fabricated testimonials do not create useful adoption and are not part of this plan. Trending placement is a third-party outcome, not a controllable acceptance check.

## Launch surfaces we own

1. GitHub organization profile: plain description, exact install command, task-specific links, FAQ, license, and limits.
2. Repository README: runnable demo, catalog, worked example, validation evidence, and install badge.
3. Saka website: install instructions on the marketing hub and beginner guide, public article, Markdown alternatives, and links from the homepage and llms.txt.
4. Each skill: a discriminating description and a task it completes independently.

These surfaces support conventional search (SEO), retrieval/citation in generated answers (GEO), and concise question answering (AEO). They improve clarity and access; they do not guarantee rankings or citations. Avoid keyword stuffing, fake reviews, and duplicate doorway pages.

## Seven-day adoption experiment

Hypothesis: a concrete local preview makes the collection useful enough for novice developer marketers to keep using it.

Day 1: publish verified artifacts and installation path. Day 2: record the supplied synthetic demo and actual prerequisites. Days 3–4: invite an explicitly authorized pilot cohort to try it; use a modest target of five completed attempts, not an adoption claim. Days 5–6: fix reproduced failures and publish the changes. Day 7: review installed → first preview → useful campaign draft outcomes from voluntary reports. Never silently collect app or recipient data.

Track public listing visibility and install counts with timestamps, voluntary completed-preview reports, time and blockers, and concrete issues resolved. Do not equate an install with an active user or a successful campaign. Revise the prompt before spending effort on broader distribution if pilots cannot complete it.
